# QuakeLens Japan

**建物の築年分布（Project PLATEAU）× 地震ハザード・表層地盤（J-SHIS）× AI防災解説（Gemini API Function Calling）**

Google AI Challenge 2026 応募作品として開発された、公的オープンデータに基づく防災情報の可視化・地域分析・自然言語解説Webアプリケーションです。

> [!IMPORTANT]
> 本ツールは個別建物の耐震診断や倒壊確率の予測を行うものではありません。公開データ（Project PLATEAU・J-SHIS・気象庁）に基づく防災情報の可視化・分析支援ツールです。

---

## 1. 対象自治体の選定理由と属性取得率

### 選定地域：**京都府京都市全域（11区）**

当初は東京23区を第一候補として、国土交通省 Project PLATEAU（[G空間情報センター CKAN](https://www.geospatial.jp/ckan/)）の `plateau-tokyo23ku-citygml-2020` および `plateau-tokyo23ku-citygml-2022` のCityGMLファイルを直接検証しました。その結果、東京23区データでは標準の建築年属性（`bldg:yearOfConstruction`）が **0%**（未整備）であることが判明しました。

そこで、全国主要自治体のPLATEAUデータを横並びで調査した結果、以下の理由から **京都市（2025年度版：`plateau-26100-kyoto-shi-2025`）** を対象地域として選定しました。

1. **最新の標準仕様・高い属性網羅率**
   - 2025年度整備・2026年5月更新（標準製品仕様書第5.0版）
   - 総建物数：**513,815棟**（242メッシュファイル全件処理 / 2,990メッシュ）
   - 建築年判明率：**80.9%**（415,456棟が判明 / **98,359棟・19.1%が不明**）
   - 建物用途判明率：**82.3%**（`82.28%` / 422,773棟）
   - 建物構造判明率：**79.1%**（`79.11%` / 406,465棟）
   - 地上階数判明率：**80.0%**（`80.04%` / 411,258棟）
   - 実測高さ判明率：**98.2%**（`98.16%` / 504,362棟）
2. **建築年区分のバランスの良さと欠損値の存在**
   - 1981年以前：**158,446棟**
   - 1982〜2000年：**131,749棟**
   - 2001年以降：**125,261棟**
   - 建築年不明：**98,359棟**（推測や補完を一切行わず「不明」として保持）
3. **市内の地震ハザード・表層地盤のコントラスト**
   - 市域全体（2,990メッシュ）の30年震度6弱以上確率（`T30_I55_PS`）は **0.5%〜58.3%**（山地最小 `0.54%` 〜 後背湿地最大 `58.29%`）の幅があり、たとえば砂礫質台地（531メッシュ平均 **5.4%**・東山区内の砂礫質台地では **5.4%〜6.7%**）であるのに対し、伏見区・山科区などの後背湿地（399メッシュ平均 **54.7%**、伏見区最大 **58.3%**・山科区最大 **52.7%**）では極めて高い確率分布を示しており、建物築年数と地盤・ハザードの重なりを直感的に分析できます。

## 2. 主な機能

1. **インタラクティブ地図（MapLibre GL JS + 地理院タイル）**
   - 築年区分による建物ポリゴンの色分け（1981年以前 / 1982〜2000年 / 2001年以降 / 建築年不明）
   - **2D平面 / 3D立体（LOD1）表示切替**：PLATEAUの実測建物高さ（`measuredHeight`・判明率98.2%）を用いた `fill-extrusion` 3D可視化に対応（カメラ傾き・回転操作可）
   - 色覚多様性（Okabe-Ito）に配慮した建物カラーパレットと紫系ハザードメッシュの明確な視覚分離
   - J-SHIS 250mメッシュオーバーレイ（「今後30年震度6弱以上確率」と「表層地盤最大速度増幅率 ARV」を切替可能）
   - 気象庁 地震発生履歴（震源・M・最大震度）のオーバーレイ表示
   - 築年区分・ハザード区分・用途区分・行政区（11区）による即時フィルタリング
2. **統計ダッシュボード（Recharts）**
   - 対象棟数・建築年判明率・建築年不明件数（分母と欠損を明示）
   - 「築年区分別棟数」「地震ハザード区分 × 築年区分」のインタラクティブグラフ（棒グラフクリックで地図フィルター連動）
3. **優先確認エリア分析（250mメッシュ単位）**
   - 統一座標系（`EPSG:6674`：JGD2011 平面直角座標系第VI系）での空間結合により、250mメッシュごとに総棟数・建築年判明率・1981年以前棟数・震度6弱以上確率・ARV・微地形区分を集計
   - 任意の重み付け危険度スコアを使わず、実測値ベースのソートで優先確認エリアを一覧表示（クリックで該当メッシュへ自動ズーム）
4. **詳細インスペクター＆公式耐震補助案内**
   - 建物・250mメッシュをクリックして建築年・構造・用途・地盤・ハザード確率を確認
   - 京都市公式の無料耐震診断（「木造住宅及び京町家の耐震診断士派遣事業」）および改修補助（「まちの匠・ぷらす」）等の確認済み公式ページへの導線を表示
   - 詳細カード内の「**AIで詳しく解説**」ボタンから、選択対象をコンテキストに含めて即座にAI解説を起動可能
5. **Gemini AI 防災解説アシスタント（SSEストリーミング × Function Calling × 数値根拠自動検証 × 地図連動）**
   - `google-genai` SDK（Interactions API・SSEリアルタイムストリーミング）と Next.js Route Handler 中継＋キープアライブ配信により、長考時・プロキシ経由でもタイムアウトしない安定したストリーミング対話を実現
   - バックエンドの実データ照会ツール（`get_area_statistics`［築年・ハザード・用途フィルター連動］, `compare_wards`, `get_priority_confirmation_areas`, `get_mesh_details`, `get_building_details`, `get_recent_earthquakes_summary`, `get_data_methodology_and_programs`）をFunction Callingで呼び出し、実行過程と参照根拠（引数・取得結果サマリー）を折りたたみカードで透明化
   - **数値・識別子・URL 自動根拠検証（`grounding.py`）**：AI応答内の数値（棟数・割合・ARV/AVS・確率）・メッシュコード・建物ID・URLを実行済みツール返却値と自動照合し、ツール未実行や未照合値がある場合は自動再確認・警告バッジで通知
   - 回答内の注目区・250mメッシュ・建物をワンクリックで地図フォーカス＆詳細取得できる **地図連動アクション（MapActions）**、ワンクリックの「現在エリアをAI診断」を搭載
   - モデル選択（`gemini-3.5-flash-lite`［高速・標準］ / `gemini-4-hydrogen` / `gemini-4-argon`）、ブラウザメモリ内の一時APIキー入力（BYOK）、アクセスコード認証、本日の共用残枠表示に対応
   - `GEMINI_API_KEY` 未設定時もダミー回答を行わず、バックエンドの実データ照会ツールを実行して正確な集計値・地図移動アクションを返却

## 5. データの扱いに関する重要な前提・制約

- **ハザード確率の定義**：`T30_I55_PS`（今後30年間に震度6弱以上の揺れに見舞われる確率）等は地震動の発生確率であり、**個別建物の倒壊確率やリアルタイム地震予知ではありません**。
- **建築年の粒度と耐震基準**：PLATEAUの `bldg:yearOfConstruction` は「年」単位のデータです。1981年6月1日施行の新耐震基準や、2000年6月1日施行の木造住宅に関する基準（接合部・耐力壁バランス等）は「月日」に依存するため、築年数のみで厳密に適合・不適合を判定していません。
- **欠損値の扱い**：建築年が未入力または異常値（`0001`・`9999`等）の建物は推測せず「建築年不明」として集計・表示しています。用途が `461`（不明）または欠損の建物も勝手に住宅扱いしていません。

## 6. セットアップ・起動方法（Mac / Linux）

前処理済みの京都市データ（`backend/data/processed/buildings.parquet`, `meshes.geojson`, `summary.json`）を同梱しているため、**APIキーなしでも地図・フィルター・統計・優先エリア分析・実データプレビューがそのまま動作します**。AI防災解説機能を利用する場合のみ `.env` に `GEMINI_API_KEY` を設定するか、ブラウザ上の「APIキー設定」から入力してください。

> [!NOTE]
> 本アプリは **2つのサーバー** で構成されています。
> - **Webアプリ画面（ブラウザで開くURL）**: `http://localhost:3000`（Next.js フロントエンド）
> - **APIサーバー**: `http://127.0.0.1:8000`（FastAPI バックエンド／API仕様: `http://127.0.0.1:8000/docs`）
>
> バックエンドだけを起動して `http://127.0.0.1:8000` を開くと案内ページが表示されます。地図とダッシュボードを表示するには **フロントエンドも起動して `http://localhost:3000` にアクセスしてください。**

### 必要環境
- Python 3.12+ & `uv`
- Node.js 20+ & `npm`

### 1) 環境変数設定（任意：AI解説・公開時の保護設定）

```bash
cp .env.example .env
# .env を開き、GEMINI_API_KEY=あなたのAPIキー を記入
```

### 2) かんたん一括起動（推奨）

リポジトリルートで `./start.sh` を実行すると、バックエンド（`:8000`）の起動待機とフロントエンドの本番ビルド＆起動（`:3000`）を順番に行います：

```bash
./start.sh
```

起動後、ブラウザで **`http://localhost:3000`** を開いてください（終了は `Ctrl + C`）。

### 3) 個別に起動する場合（2ターミナル）

**ターミナル1：バックエンド起動（FastAPI: `http://127.0.0.1:8000`）**

```bash
cd backend
uv sync
uv run uvicorn app.main:app --host 127.0.0.1 --port 8000
```

> データパイプラインをゼロから再実行して最新データを取得・再構築する場合：
> ```bash
> cd backend
> uv run python scripts/fetch_and_build.py
> ```

**ターミナル2：フロントエンド起動（Next.js: `http://localhost:3000`）**

```bash
cd frontend
npm install
npm run dev
# 本番ビルドで起動する場合: npm run build && npm run start -- --port 3000
```

起動後、ブラウザで **`http://localhost:3000`** を開きます。

## 7. 公開運用時のAPI保護・費用制御設定

不特定多数へ公開した際の Gemini API 不正利用・課金急増を防ぐため、以下の多層保護機構を標準搭載しています（設定はすべて `.env` で変更可能）。

| 環境変数 | デフォルト値 | 役割 |
|---|---|---|
| `GEMINI_API_KEY` | 未設定 | サーバー側の共用 Gemini API キー（`.gitignore` 対象） |
| `AI_PUBLIC_SERVER_KEY_ENABLED` | `true` | `false` にすると共用キーを無効化し、利用者の個人キー持込（BYOK）のみでAI稼働 |
| `AI_ACCESS_CODE` | 空（無効） | 設定時、共用キー利用に `X-Ai-Access-Code` 一致を必須化（BYOK時は不要） |
| `AI_ALLOW_PREMIUM_MODELS` | `false` | `false` の場合、共用キーでは `gemini-3.5-flash-lite` のみ許可（`gemini-4-*` は個人キー持込または `true` 時のみ） |
| `AI_RATE_LIMIT_PER_MIN` | `8` | 共用キー利用時の IP あたり 1分間リクエスト上限（超過時 `429` + `Retry-After`） |
| `AI_RATE_LIMIT_PER_HOUR` | `40` | 共用キー利用時の IP あたり 1時間リクエスト上限 |
| `AI_DAILY_BUDGET_REQUESTS` | `300` | 共用キー利用時のサーバー全体 1日合計リクエスト上限（到達時はBYOK案内） |
| `AI_MAX_CONCURRENT_PER_IP` | `2` | 同一 IP からの同時ストリーミング接続上限 |
| `AI_MAX_CONCURRENT_GLOBAL` | `15` | サーバー全体の同時 AI 実行上限 |
| `AI_MAX_MESSAGE_CHARS` | `1200` | 1回の質問メッセージ最大文字数（超過時 `413`） |
| `AI_MAX_OUTPUT_TOKENS` | `1536` | Gemini 応答の最大出力トークン数上限（ツールループも最大4ターンに制限） |
| `CORS_ALLOW_ORIGINS` | `http://localhost:3000,http://127.0.0.1:3000` | 許可するフロントエンドオリジン（カンマ区切り・ワイルドカード `*` 廃止） |
| `AI_TRUST_PROXY_HEADERS` | `false` | リバースプロキシ配下で `X-Forwarded-For` を信頼する場合に `true`（ループバック接続は自動許可） |

> [!TIP]
> インターネット公開時は、上記に加えて **Google Cloud / Google AI Studio 側でも APIキーの「API制限（Generative Language API のみに限定）」および「課金予算アラート／クォータ上限」を設定** することを推奨します。

## 8. アプリの正しい使い方

1. **初期表示・全体俯瞰（初期ズーム `14.8`）**：起動直後から建物ポリゴンと250m地震ハザードメッシュが重ねて表示され、上部KPIと右パネルの「統計・エリア」タブで対象棟数・築年判明率・クロス集計グラフを確認できます。
2. **レイヤー・地域・2D/3D切替（左パネル／地図右上コントロール）**：
   - 行政区（11区）を切り替えると、地図が該当区へ移動し統計・優先確認エリアも連動更新されます。
   - 建物レイヤーの「**2D 平面 / 3D 立体**」ボタンを切り替えると、PLATEAUの実測高さを用いた3D建物表示（`fill-extrusion`）になります。
   - 250mメッシュは「震度6弱+確率」と「表層地盤増幅率（ARV）」をワンクリックで切り替えられます。
   - 「気象庁 直近震源履歴」をONにすると、直近の震源円が地図上に重なります。
3. **個別建物の確認（ズーム `13.5` 以上、またはメッシュクリック）**：
   - ズームレベル `13.5` 以上で表示される建物ポリゴンや250mメッシュをクリックすると、右側の「詳細・補助」タブに建築年・構造・用途・地盤・ハザード確率・京都市公式の耐震診断/補助制度リンクが表示されます。
   - 建物・メッシュ詳細カード内の「**この建物／メッシュをAIで詳しく解説**」を押すと、選択対象を引き継いでAI解説タブが起動します。
4. **優先確認エリアの抽出（右パネル「統計・エリア」タブ下部）**：
   - 「高ハザード×1981以前順」「1981以前棟数順」「震度6弱+確率順」等で250mメッシュを並び替え、行をクリックすると該当エリアへ直接ズームインします。
5. **AI防災解説（ヘッダー「AI防災解説」／右パネル「AI防災解説」タブ）**：
   - 画面上のモデル選択（標準は高速な `gemini-3.5-flash-lite`）、「現在エリアをAI診断」ボタン、質問例チップ、または自由入力から質問すると、SSEストリーミングでリアルタイムに回答が生成されます。
   - 「参照データ根拠（Function Calling）」折りたたみカードで実行されたツールと根拠サマリーを確認でき、回答下の地図連動アクションボタンから注目区・250mメッシュ・建物へ直接ジャンプできます。
   - 公開運用で制限がある場合や個人キーを使いたい場合は、上部の「APIキー設定／認証設定」ボタンからブラウザメモリ上のみで APIキー（BYOK）やアクセスコードを入力できます。
